Concepte fonamental

1. Què és un ORM?

🔄

ORM

Object-Relational Mapping

Tècnica que converteix automàticament entre objectes Java i files d'una taula SQL. Tu treballes amb objectes; l'ORM genera el SQL.

ORM significa Object-Relational Mapping: un pont automàtic entre el món dels objectes (Java) i el món relacional (SQL/MySQL).

En comptes d'escriure SQL a mà i mapejar cada ResultSet a un objecte (com fèiem amb JdbcTemplate), l'ORM ho fa per tu:

Amb JdbcTemplate (Sessions 2-3)
Objecte Java ←── tu escrius el RowMapper ──→ Taula SQL

Amb JPA/ORM (Sessions 4-5)
Objecte Java ←── automàtic (@Entity) ──→ Taula SQL
ConcepteSignificat
JPAJava Persistence API — l'estàndard/especificació (com una interfície)
HibernateLa implementació més popular de JPA (com la classe que implementa la interfície)
Spring Data JPACapa de Spring que simplifica encara més l'ús de JPA/Hibernate
Analogia JPA és el contracte. Hibernate és l'empresa que l'executa. Spring Data JPA és l'agent que contracta Hibernate i ens estalvia les trucades de telèfon.
Entitats

2. @Entity: la classe és la taula

Amb JPA, una classe Java anotada amb @Entity representa directament una taula de la BBDD. Cada atribut és una columna.

Abans (Sessió 1-3): classe POJO

public class Product {
    private Long id;
    private String name;
    private Double price;
    private String description;
    private String category;
    private Integer stock;
    // constructors, getters, setters
}

Ara: classe @Entity

@Entity
@Table(name = "products")
public class Product {
    @Id
    @GeneratedValue(strategy =
        GenerationType.IDENTITY)
    private Long id;
    
    @Column(nullable = false,
            length = 100)
    private String name;
    private Double price;
    private String description;
    private String category;
    private Integer stock;
    // constructors, getters, setters
}

2.1 Anotacions d'entitat

2.2 L'entitat completa

package com.curs.products.model;

import jakarta.persistence.*;

@Entity
@Table(name = "products")
public class Product {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, length = 100)
    private String name;

    @Column(nullable = false)
    private Double price;

    private String description;

    @Column(length = 50)
    private String category;

    @Column(columnDefinition = "INT DEFAULT 0")
    private Integer stock;

    // Constructor buit OBLIGATORI per JPA
    public Product() {}

    // Constructor amb camps (sense id, el genera la BBDD)
    public Product(String name, Double price, String description,
                   String category, Integer stock) {
        this.name = name;
        this.price = price;
        this.description = description;
        this.category = category;
        this.stock = stock;
    }

    // Getters i Setters (tots necessaris per JPA)
    public Long getId() { return id; }
    public void setId(Long id) { this.id = id; }

    public String getName() { return name; }
    public void setName(String name) { this.name = name; }

    public Double getPrice() { return price; }
    public void setPrice(Double price) { this.price = price; }

    public String getDescription() { return description; }
    public void setDescription(String description) { this.description = description; }

    public String getCategory() { return category; }
    public void setCategory(String category) { this.category = category; }

    public Integer getStock() { return stock; }
    public void setStock(Integer stock) { this.stock = stock; }
}
⚠️ Requisits de JPA 1. La classe ha de tenir un constructor buit (sense paràmetres).
2. Tots els camps han de tenir getters i setters.
3. Ha de tenir un camp anotat amb @Id.

spring.datasource.url=jdbc:mysql://localhost:3306/products_db
spring.datasource.username=root
spring.datasource.password=1234

# ─── NOU: Configuració JPA ───

# IMPORTANT: Mostra el SQL que genera Hibernate als logs
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true

# Gestió de l'schema: "update" adapta la taula als canvis de l'entitat
spring.jpa.hibernate.ddl-auto=update
ddl-auto: opcions none → No toca l'schema (producció)
update → Crea/modifica taules segons les @Entity (desenvolupament)
create → Esborra i recrea taules en cada arrencada
create-drop → Igual que create, però esborra tot en aturar l'app
💡 show-sql=true Sempre activat a classe. Cada cop que JPA fa una operació, veureu el SQL real als logs. Això connecta JPA amb el SQL que ja coneixeu i evita que l'ORM sigui una "caixa negra".

4. JpaRepository: CRUD automàtic

El repositori JPA complet:

public interface ProductRepository
        extends JpaRepository<Product, Long> {
    // Buit. Spring genera tot el CRUD.
}

3 línies. Substitueix les ~80 línies de les Sessions 2 i 3.

Al estendre JpaRepository<Product, Long>, Spring genera automàticament tots aquests mètodes:

Mètode JPASQL generatEquivalent JdbcTemplate
findAll() SELECT * FROM products jdbc.query("SELECT * FROM products", mapper)
findById(1L) SELECT * FROM products WHERE id=1 jdbc.query("...WHERE id=?", mapper, 1)
save(product) INSERT INTO products ... (si id és null)
UPDATE products ... (si id existeix)		 jdbc.update("INSERT...", params)
deleteById(1L) DELETE FROM products WHERE id=1 jdbc.update("DELETE...WHERE id=?", 1)
count() SELECT COUNT(*) FROM products jdbc.queryForObject("SELECT COUNT(*)", Integer.class)
existsById(1L) SELECT COUNT(*)... WHERE id=1 No teníem equivalent directe
findAll(Sort.by("price")) SELECT * FROM products ORDER BY price jdbc.query("...ORDER BY price", mapper)
Com funciona? Spring llegeix la interfície, veu que estén JpaRepository, i genera una classe d'implementació automàticament en temps d'execució. Tu mai escrius la implementació. El tipus genèric <Product, Long> indica l'entitat i el tipus de la clau primària.
Codi en viu

5. Actualitzar el Service

El ProductService ara fa servir el JpaRepository en lloc del nostre repositori manual:

@Service
public class ProductService {

    @Autowired
    private ProductRepository productRepository;

    public List<Product> getAll() {
        return productRepository.findAll();
    }

    public Optional<Product> getById(Long id) {
        return productRepository.findById(id);
    }

    public Product create(Product product) {
        return productRepository.save(product);
        // save() retorna l'objecte amb l'id assignat automàticament
    }

    public Product update(Long id, Product updatedProduct) {
        // save() fa INSERT si l'id no existeix, UPDATE si existeix
        updatedProduct.setId(id);
        return productRepository.save(updatedProduct);
    }

    public void delete(Long id) {
        productRepository.deleteById(id);
    }

    public long count() {
        return productRepository.count();
    }

    public boolean exists(Long id) {
        return productRepository.existsById(id);
    }
}
💡 save() és intel·ligent save(product) mira l'id:
→ Si id == null: fa INSERT (producte nou)
→ Si id existeix a la BBDD: fa UPDATE

6. El gran contrast: JdbcTemplate vs JPA

Sessions 2-3: JdbcTemplate

@Repository
public class ProductRepository {
    @Autowired
    private JdbcTemplate jdbc;

    private final RowMapper<Product>
      productMapper = (rs, rn) ->
        new Product(
          rs.getLong("id"),
          rs.getString("name"),
          rs.getDouble("price"),
          rs.getString("description"),
          rs.getString("category"),
          rs.getInt("stock"));

    public List<Product> findAll() {
      return jdbc.query(
        "SELECT * FROM products",
        productMapper);
    }

    public Optional<Product> findById(
        Long id) {
      return jdbc.query(
        "SELECT * FROM products" +
        " WHERE id=?",
        productMapper, id)
        .stream().findFirst();
    }

    public int save(Product p) {
      return jdbc.update(
        "INSERT INTO products" +
        " (name,price,description," +
        "category,stock)" +
        " VALUES (?,?,?,?,?)",
        p.getName(), p.getPrice(),
        p.getDescription(),
        p.getCategory(),
        p.getStock());
    }

    public int update(Long id,
        Product p) {
      return jdbc.update(
        "UPDATE products" +
        " SET name=?, price=?," +
        " description=?," +
        " category=?, stock=?" +
        " WHERE id=?",
        p.getName(), p.getPrice(),
        p.getDescription(),
        p.getCategory(),
        p.getStock(), id);
    }

    public int deleteById(Long id) {
      return jdbc.update(
        "DELETE FROM products" +
        " WHERE id=?", id);
    }
}

📋 Resum de la sessió

  • 1. ORM (Object-Relational Mapping) mapeja automàticament objectes Java ↔ taules SQL.
  • 2. @Entity + @Id transformen una classe en una entitat JPA vinculada a una taula.
  • 3. JpaRepository<T, ID> proporciona CRUD complet sense escriure SQL.
  • 4. save() és intel·ligent: fa INSERT o UPDATE segons si l'entitat ja existeix.
  • 5. show-sql=true sempre activat: veure el SQL generat és essencial per entendre el que fa l'ORM.
