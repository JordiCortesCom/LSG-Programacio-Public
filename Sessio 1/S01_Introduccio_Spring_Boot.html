Context

1. Per què Spring Boot?

🏗️

Framework vs Llibreria

Clica per veure la diferència

Llibreria: Tu crides el codi (ex: Math.random()).

Framework: El framework crida el teu codi. Tu defineixes què fa, Spring decideix quan i com s'executa.

Fins ara heu programat en Java "pur": vosaltres creàveu els objectes, gestionàveu les connexions, i controlàveu tot el flux d'execució. Això funciona per a programes petits, però quan el projecte creix, el codi es torna repetitiu i difícil de mantenir.

Spring Boot és el framework Java més utilitzat a la indústria. Més del 60% dels projectes Java empresarials el fan servir. Arrenca amb una configuració mínima i et permet centrar-te en la lògica de negoci.

Idea clau Spring Boot no és un llenguatge nou. És Java amb superpowers: configuració automàtica, gestió d'objectes, i un servidor web integrat.

Teoria fonamental

3. IoC i Injecció de Dependències

Aquests dos conceptes són el cor de Spring. Si els enteneu, la resta del framework encaixa naturalment.

3.1 Inversió de Control (IoC)

En Java "normal", tu crees els objectes:

// TU crees l'objecte, TU el gestiones
ProductService service = new ProductService();
ProductController controller = new ProductController(service);

Amb Spring, Spring crea els objectes per tu i te'ls dona quan els necessites:

// Spring crea ProductService automàticament
// Spring crea ProductController i li injecta el service
// Tu no fas "new" en cap moment
Java Tradicional
Tu → new Service() → new Controller(service)

Spring (IoC)
Spring Container → crea Service → crea Controller → els connecta

3.2 Injecció de Dependències (DI)

L'Injecció de Dependències és el mecanisme concret: Spring detecta que un objecte necessita un altre i li'l injecta automàticament.

3.3 Les anotacions clau

AnotacióOn es posaQuè fa
@Component Qualsevol classe Diu a Spring: "crea una instància d'aquesta classe i guarda-la"
@Service Classe de lògica de negoci Igual que @Component però amb nom semàntic (lògica)
@Repository Classe d'accés a dades Igual que @Component però amb nom semàntic (dades)
@RestController Classe que rep peticions HTTP @Component + gestió HTTP (entrada/sortida JSON)
@Autowired Atribut o constructor "Spring, injecta'm aquí l'objecte que necessito"
Analogia Imagina Spring com un magatzem intel·ligent. Tu etiquetes les caixes (@Service, @Repository) i dius on les necessites (@Autowired). El magatzemer (Spring Container) les porta on calgui, sense que hagis de moure-les tu.

4. La nostra primera API REST

Construïm una API per gestionar productes. Sense base de dades encara: les dades viuen en memòria dins d'una llista Java.

4.1 El Model: Product.java

package com.curs.products.model;

public class Product {

    private Long id;
    private String name;
    private Double price;
    private String description;
    private String category;

    // Constructor buit (Spring el necessita per deserialitzar JSON)
    public Product() {}

    // Constructor amb tots els camps
    public Product(Long id, String name, Double price,
                   String description, String category) {
        this.id = id;
        this.name = name;
        this.price = price;
        this.description = description;
        this.category = category;
    }

    // Getters i Setters (IntelliJ: Alt+Insert → Getters and Setters)
    public Long getId() { return id; }
    public void setId(Long id) { this.id = id; }

    public String getName() { return name; }
    public void setName(String name) { this.name = name; }

    public Double getPrice() { return price; }
    public void setPrice(Double price) { this.price = price; }

    public String getDescription() { return description; }
    public void setDescription(String description) { this.description = description; }

    public String getCategory() { return category; }
    public void setCategory(String category) { this.category = category; }
}

4.2 El Servei: ProductService.java

package com.curs.products.service;

import com.curs.products.model.Product;
import org.springframework.stereotype.Service;
import java.util.ArrayList;
import java.util.List;
import java.util.Optional;

@Service    // ← Spring: "crea una instància d'aquesta classe"
public class ProductService {

    // Simulem una BBDD amb una llista en memòria
    private List<Product> products = new ArrayList<>(List.of(
        new Product(1L, "Poma Golden", 1.20, "Poma dolça", "Fruita"),
        new Product(2L, "Plàtan", 0.90, "Plàtan de Canàries", "Fruita"),
        new Product(3L, "Llet Sencera", 1.05, "Llet 1L", "Lactis")
    ));

    private Long nextId = 4L;

    public List<Product> getAll() {
        return products;
    }

    public Optional<Product> getById(Long id) {
        return products.stream()
                .filter(p -> p.getId().equals(id))
                .findFirst();
    }

    public Product create(Product product) {
        product.setId(nextId++);
        products.add(product);
        return product;
    }

    public boolean delete(Long id) {
        return products.removeIf(p -> p.getId().equals(id));
    }
}

4.3 El Controlador: ProductController.java

package com.curs.products.controller;

import com.curs.products.model.Product;
import com.curs.products.service.ProductService;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;
import java.util.List;

@RestController                     // ← Controlador que retorna JSON
@RequestMapping("/api/products")    // ← Ruta base: /api/products
public class ProductController {

    @Autowired                      // ← "Spring, injecta'm el ProductService"
    private ProductService productService;

    // GET /api/products
    @GetMapping
    public List<Product> getAll() {
        return productService.getAll();
    }

    // GET /api/products/1
    @GetMapping("/{id}")
    public ResponseEntity<Product> getById(@PathVariable Long id) {
        return productService.getById(id)
                .map(ResponseEntity::ok)                      // 200 OK
                .orElse(ResponseEntity.notFound().build());    // 404 Not Found
    }

    // POST /api/products  (cos: JSON del producte)
    @PostMapping
    public Product create(@RequestBody Product product) {
        return productService.create(product);
    }

    // DELETE /api/products/1
    @DeleteMapping("/{id}")
    public ResponseEntity<Void> delete(@PathVariable Long id) {
        if (productService.delete(id)) {
            return ResponseEntity.noContent().build();         // 204 No Content
        }
        return ResponseEntity.notFound().build();              // 404 Not Found
    }
}

5. Provar l'API amb IntelliJ HTTP Client

IntelliJ inclou un client HTTP integrat. Crea un fitxer .http al projecte i escriu-hi les peticions:

### Llistar tots els productes
GET http://localhost:8080/api/products
Accept: application/json

### Obtenir producte per ID
GET http://localhost:8080/api/products/1
Accept: application/json

### Crear un producte nou
POST http://localhost:8080/api/products
Content-Type: application/json

{
  "name": "Oli d'Oliva",
  "price": 4.75,
  "description": "Oli verge extra 1L",
  "category": "Condiments"
}

### Eliminar un producte
DELETE http://localhost:8080/api/products/2

### Demanar un producte que no existeix (esperar 404)
GET http://localhost:8080/api/products/999
Accept: application/json

Per executar cada petició, clica la icona ▶ verda al costat de cada bloc ###.

💡 Per què no Postman? Els fitxers .http són text pla i entren al projecte. Es poden versionar amb Git, compartir, i lliurar com a evidència de proves.

public List<Product> getByCategory(String category) {

Crea un endpoint GET que rebi la categoria com a paràmetre de query (/api/products/search?category=Fruita):

📋 Resum de la sessió

  • 1. Spring Boot és un framework que gestiona l'arrencada, la configuració i el cicle de vida dels objectes Java.
  • 2. IoC: Spring crea i gestiona els objectes (Beans). Tu no fas new.
  • 3. DI: Spring detecta dependències entre objectes i les connecta automàticament amb @Autowired.
  • 4. L'arquitectura Controller → Service → Repository separa responsabilitats.
  • 5. Una API REST es construeix amb @GetMapping, @PostMapping, @DeleteMapping, etc.
