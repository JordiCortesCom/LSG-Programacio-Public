Queries Personalitzades amb JPA

El CRUD estàndard és potent, però no sempre suficient. Avui aprendrem a crear queries personalitzades sense escriure SQL — i quan sí que cal escriure'l.

Punts Clau de la Sessió

  • 🔮 Derived Query Methods: Spring genera SQL a partir del nom del mètode.
  • 📝 @Query (JPQL): query orientada a objectes, no a taules.
  • 🗃️ @Query (nativeQuery): SQL pur quan ho necessitem.
  • 🏗️ Pràctica integradora final.
Màgia amb sentit

1. Derived Query Methods

Spring Data JPA pot generar queries automàticament a partir del nom del mètode. Només cal seguir una convenció de noms:

public interface ProductRepository extends JpaRepository<Product, Long> {

    // SELECT * FROM products WHERE name = ?
    List<Product> findByName(String name);

    // SELECT * FROM products WHERE category = ?
    List<Product> findByCategory(String category);

    // SELECT * FROM products WHERE price < ?
    List<Product> findByPriceLessThan(Double maxPrice);

    // SELECT * FROM products WHERE price > ?
    List<Product> findByPriceGreaterThan(Double minPrice);

    // SELECT * FROM products WHERE price BETWEEN ? AND ?
    List<Product> findByPriceBetween(Double min, Double max);

    // SELECT * FROM products WHERE name LIKE '%keyword%'
    List<Product> findByNameContaining(String keyword);

    // SELECT * FROM products WHERE stock > 0
    List<Product> findByStockGreaterThan(Integer minStock);

    // SELECT * FROM products ORDER BY price ASC
    List<Product> findAllByOrderByPriceAsc();

    // SELECT * FROM products WHERE category = ? ORDER BY price DESC
    List<Product> findByCategoryOrderByPriceDesc(String category);

    // SELECT COUNT(*) FROM products WHERE category = ?
    long countByCategory(String category);

    // SELECT * FROM products WHERE category = ? AND price < ?
    List<Product> findByCategoryAndPriceLessThan(String category, Double maxPrice);
}
Com funciona? Spring llegeix el nom del mètode, el descompon en paraules clau i genera el SQL: 
findByNameContaining("poma")
│     │    │
│     │    └── LIKE '%poma%'
│     └── WHERE name
└── SELECT * FROM products

findByCategoryAndPriceLessThan("Fruita", 2.0)
│     │         │   │
│     │         │   └── price < 2.0
│     │         └── AND
│     └── WHERE category = 'Fruita'
└── SELECT * FROM products

Queries explícites

2. @Query amb JPQL

Quan els noms de mètode es fan massa llargs o la query és complexa, podem escriure-la explícitament amb JPQL (Java Persistence Query Language).

JPQL és com SQL, però orientat a entitats (classes Java), no a taules:

SQL (taules)JPQL (entitats)
SELECT * FROM productsSELECT p FROM Product p
products.namep.name (camp Java, no columna)
SELECT COUNT(*)SELECT COUNT(p)

2.1 Exemples amb @Query

public interface ProductRepository extends JpaRepository<Product, Long> {

    // JPQL: buscar productes cars
    @Query("SELECT p FROM Product p WHERE p.price > :minPrice")
    List<Product> findExpensive(@Param("minPrice") Double minPrice);

    // JPQL: buscar per nom (case-insensitive)
    @Query("SELECT p FROM Product p WHERE LOWER(p.name) LIKE LOWER(CONCAT('%', :keyword, '%'))")
    List<Product> searchByName(@Param("keyword") String keyword);

    // JPQL: preu mitjà per categoria
    @Query("SELECT AVG(p.price) FROM Product p WHERE p.category = :category")
    Double averagePriceByCategory(@Param("category") String category);

    // JPQL: categories úniques
    @Query("SELECT DISTINCT p.category FROM Product p")
    List<String> findAllCategories();

    // JPQL: productes amb stock baix
    @Query("SELECT p FROM Product p WHERE p.stock < :threshold ORDER BY p.stock ASC")
    List<Product> findLowStock(@Param("threshold") Integer threshold);
}
@Param: noms de paràmetre Amb JPQL, els paràmetres es referencien amb :nom (no amb ?). L'anotació @Param("nom") vincula el paràmetre Java amb el :nom de la query.
SQL pur

3. @Query amb SQL natiu

Per a queries molt específiques de MySQL o quan JPQL no és suficient, podem escriure SQL pur:

public interface ProductRepository extends JpaRepository<Product, Long> {

    // SQL natiu: producte aleatori
    @Query(value = "SELECT * FROM products ORDER BY RAND() LIMIT 1",
           nativeQuery = true)
    Optional<Product> findRandom();

    // SQL natiu: top N més cars
    @Query(value = "SELECT * FROM products ORDER BY price DESC LIMIT :limit",
           nativeQuery = true)
    List<Product> findTopExpensive(@Param("limit") int limit);

    // SQL natiu: resum per categoria
    @Query(value = "SELECT category, COUNT(*) as total, AVG(price) as avg_price " +
                   "FROM products GROUP BY category",
           nativeQuery = true)
    List<Object[]> getCategorySummary();
}

3.1 Quan usar cada tipus

TipusQuan usar-loExemple
Derived Method Queries simples (1-2 condicions) findByCategory(c)
@Query JPQL Queries complexes portàtils (funcionen amb qualsevol BBDD) @Query("SELECT p FROM Product p WHERE...")
@Query nativeQuery Funcions específiques de MySQL (RAND, LIMIT, funcions pròpies) @Query(value="SELECT...", nativeQuery=true)
⚠️ nativeQuery = acoblament Les native queries utilitzen SQL específic de MySQL. Si canvies a PostgreSQL o Oracle, hauràs de reescriure-les. JPQL és més portable. Usa native queries només quan cal.
Modificacions amb @Query

4. UPDATE i DELETE amb @Query

Per defecte, @Query és per a SELECT. Per a UPDATE o DELETE, cal afegir @Modifying:

public interface ProductRepository extends JpaRepository<Product, Long> {

    // UPDATE amb JPQL
    @Modifying
    @Transactional
    @Query("UPDATE Product p SET p.price = p.price * (1 - :percent / 100) WHERE p.category = :category")
    int applyDiscount(@Param("category") String category,
                      @Param("percent") Double percent);

    // DELETE amb JPQL
    @Modifying
    @Transactional
    @Query("DELETE FROM Product p WHERE p.stock = 0")
    int deleteOutOfStock();

    // UPDATE natiu
    @Modifying
    @Transactional
    @Query(value = "UPDATE products SET stock = stock + :units WHERE id = :id",
           nativeQuery = true)
    int increaseStock(@Param("id") Long id, @Param("units") int units);
}
Regla: @Modifying + @Transactional Qualsevol @Query que modifiqui dades (UPDATE/DELETE) necessita:
1. @Modifying — indica que no és un SELECT
2. @Transactional — les modificacions requereixen transacció

5. Visió global: les 3 maneres de fer queries

Fem la mateixa query ("productes de la categoria Fruita amb preu menor a 2€") de les 3 maneres:

// 1️⃣ Derived Method (nom del mètode → SQL autogenerat)
List<Product> findByCategoryAndPriceLessThan(String category, Double maxPrice);

// 2️⃣ JPQL (query explícita orientada a objectes)
@Query("SELECT p FROM Product p WHERE p.category = :cat AND p.price < :max")
List<Product> findCheapByCategory(@Param("cat") String category,
                                    @Param("max") Double maxPrice);

// 3️⃣ SQL natiu (SQL pur de MySQL)
@Query(value = "SELECT * FROM products WHERE category = :cat AND price < :max",
       nativeQuery = true)
List<Product> findCheapByCategoryNative(@Param("cat") String category,
                                         @Param("max") Double maxPrice);

Les tres generen el mateix SQL.

La diferència és quant de control necessites i quanta portabilitat vols.

Regla general: comença amb derived methods. Si no arribes, JPQL. Si JPQL no pot, SQL natiu.
