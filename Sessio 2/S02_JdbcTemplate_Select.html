Configuració

1. Connectar Spring Boot a MySQL

A la Sessió 1, les dades vivien en una ArrayList en memòria. Ara connectem a una base de dades real. Spring Boot necessita dues coses: dependències i configuració.

1.1 Dependències al pom.xml

<!-- Dóna accés a JdbcTemplate -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-jdbc</artifactId>
</dependency>

<!-- Driver de MySQL: permet a Java parlar amb MySQL -->
<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <scope>runtime</scope>
</dependency>

1.2 Configuració a application.properties 

# Connexió a MySQL
spring.datasource.url=jdbc:mysql://localhost:3306/products_db
spring.datasource.username=root
spring.datasource.password=1234

# El driver es detecta automàticament a partir de la URL
Què passa per darrere? Amb aquestes 3 línies, Spring Boot crea automàticament un pool de connexions (HikariCP): un conjunt de connexions pre-obertes a MySQL que es reutilitzen. Tu no obres ni tanques connexions mai.

1.3 Preparar la BBDD

Abans d'arrencar l'aplicació, executeu el products_db.sql a MySQL Workbench per crear la taula i les dades inicials.

Concepte clau

2. Què és JdbcTemplate?

🔧

JDBC vs JdbcTemplate

Clica per comparar

JDBC (java.sql): tu obres connexió, crees Statement, iteres ResultSet, tanques tot.

JdbcTemplate: tu escrius el SQL i el mapeig. Spring fa la resta.

JdbcTemplate és una classe de Spring que simplifica l'execució de SQL. Tu escrius el SQL exacte que vols executar, i Spring gestiona la connexió, l'execució i el tancament de recursos.

Penseu-hi com un assistent: tu li dius "executa aquest SQL i transforma cada fila en un objecte Product", i ell ho fa.

❌ Sense Spring (JDBC pur)

Connection conn = null;
Statement stmt = null;
ResultSet rs = null;
try {
    conn = DriverManager
        .getConnection(url, user, pass);
    stmt = conn.createStatement();
    rs = stmt.executeQuery(
        "SELECT * FROM products");
    while (rs.next()) {
        // Mapejar cada fila...
    }
} catch (SQLException e) {
    e.printStackTrace();
} finally {
    // Tancar rs, stmt, conn...
    // (si no, memory leak!)
}

✅ Amb JdbcTemplate

List<Product> products = 
    jdbc.query(
        "SELECT * FROM products",
        (rs, rowNum) -> new Product(
            rs.getLong("id"),
            rs.getString("name"),
            rs.getDouble("price"),
            rs.getString("description"),
            rs.getString("category"),
            rs.getInt("stock")
        )
    );


// Ja està. Connexió gestionada.
// Recursos tancats. Errors gestionats.
💡 Observa El SQL és idèntic en ambdós casos. La diferència és tot el que l'envolta: connexions, try/catch, tancament. JdbcTemplate elimina tot això.
Codi en viu

3. El Repositori: ProductRepository

Substituïm la llista en memòria de la Sessió 1 per una classe que parla amb MySQL.

3.1 Estructura bàsica

package com.curs.products.repository;

import com.curs.products.model.Product;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.stereotype.Repository;
import java.util.List;
import java.util.Optional;

@Repository     // ← Spring: "aquesta classe fa accés a dades"
public class ProductRepository {

    @Autowired
    private JdbcTemplate jdbc;  // ← Spring configura i injecta automàticament
}
D'on surt el JdbcTemplate? Spring Boot el crea automàticament quan detecta les dependències spring-boot-starter-jdbc + un driver de BBDD al pom.xml i la configuració a application.properties. Tu no el crees: li demanes amb @Autowired.

3.2 SELECT tots els productes

public List<Product> findAll() {
    String sql = "SELECT * FROM products";

    return jdbc.query(sql, (rs, rowNum) -> new Product(
        rs.getLong("id"),
        rs.getString("name"),
        rs.getDouble("price"),
        rs.getString("description"),
        rs.getString("category"),
        rs.getInt("stock")
    ));
}

El segon paràmetre de jdbc.query() és un RowMapper: una funció que transforma una fila del ResultSet en un objecte Java. Amb una lambda és molt concís.

3.3 SELECT per ID

public Optional<Product> findById(Long id) {
    String sql = "SELECT * FROM products WHERE id = ?";

    List<Product> results = jdbc.query(sql, (rs, rowNum) -> new Product(
        rs.getLong("id"),
        rs.getString("name"),
        rs.getDouble("price"),
        rs.getString("description"),
        rs.getString("category"),
        rs.getInt("stock")
    ), id);     // ← el valor que substitueix el ?

    return results.stream().findFirst();
}
⚠️ Per què ? i no concatenar? Mai concateneu valors directament a la query: 
// ❌ PERILL: SQL Injection
String sql = "SELECT * FROM products WHERE id = " + id;

// ✅ SEGUR: Paràmetre ?
String sql = "SELECT * FROM products WHERE id = ?";
jdbc.query(sql, mapper, id);
Amb ?, el driver de MySQL escapa el valor automàticament. Un atacant no pot injectar SQL maliciós.

3.4 SELECT amb filtre per nom

public List<Product> findByNameContaining(String keyword) {
    String sql = "SELECT * FROM products WHERE name LIKE ?";

    return jdbc.query(sql, (rs, rowNum) -> new Product(
        rs.getLong("id"),
        rs.getString("name"),
        rs.getDouble("price"),
        rs.getString("description"),
        rs.getString("category"),
        rs.getInt("stock")
    ), "%" + keyword + "%");    // ← els % van al valor, no al SQL
}

3.5 SELECT amb queryForObject

Per a queries que retornen un sol valor escalar (un número, un text): 

// Comptar productes
public int count() {
    String sql = "SELECT COUNT(*) FROM products";
    return jdbc.queryForObject(sql, Integer.class);
}

// Preu promig
public Double averagePrice() {
    String sql = "SELECT AVG(price) FROM products";
    return jdbc.queryForObject(sql, Double.class);
}
Bones pràctiques

4. Extreure el RowMapper

Heu notat que el mateix lambda de mapeig es repeteix a cada mètode? El podem extreure com a atribut de la classe: 

@Repository
public class ProductRepository {

    @Autowired
    private JdbcTemplate jdbc;

    // Definim el mapper una sola vegada
    private final RowMapper<Product> productMapper = (rs, rowNum) -> new Product(
        rs.getLong("id"),
        rs.getString("name"),
        rs.getDouble("price"),
        rs.getString("description"),
        rs.getString("category"),
        rs.getInt("stock")
    );

    public List<Product> findAll() {
        return jdbc.query("SELECT * FROM products", productMapper);
    }

    public Optional<Product> findById(Long id) {
        List<Product> results = jdbc.query(
            "SELECT * FROM products WHERE id = ?", productMapper, id
        );
        return results.stream().findFirst();
    }

    public List<Product> findByNameContaining(String keyword) {
        return jdbc.query(
            "SELECT * FROM products WHERE name LIKE ?",
            productMapper, "%" + keyword + "%"
        );
    }
}
💡 Principi DRY Don't Repeat Yourself. El RowMapper definit com a atribut es reutilitza a tots els mètodes. Si afegim un camp a la taula, només cal tocar un lloc.

5. Connectar les 3 capes

El ProductService ara crida al ProductRepository en comptes d'usar la llista en memòria: 

@Service
public class ProductService {

    @Autowired
    private ProductRepository productRepository;

    public List<Product> getAll() {
        return productRepository.findAll();
    }

    public Optional<Product> getById(Long id) {
        return productRepository.findById(id);
    }

    public List<Product> searchByName(String keyword) {
        return productRepository.findByNameContaining(keyword);
    }

    public int count() {
        return productRepository.count();
    }
}

6. Completa el codi: pas a pas

Construïm un mètode que busca productes per categoria i preu màxim.

Pas 1: Escriure el SQL

Quina clàusula SQL filtra per dues condicions simultàniament?

public List<Product> findByCategoryAndMaxPrice(String category, Double maxPrice) {
    String sql = "SELECT * FROM products WHERE category = ?  price <= ?";
    return jdbc.query(sql, productMapper, category, maxPrice);
}

Pas 2: L'endpoint

Quina anotació de paràmetre fa servir Spring per llegir ?category=Fruita&maxPrice=2.0 de la URL? 

@GetMapping("/filter")
public List<Product> filter(
         String category,
        @RequestParam Double maxPrice) {
    return productService.findByCategoryAndMaxPrice(category, maxPrice);
}

Escriu la petició per buscar productes de la categoria "Fruita" amb preu màxim 1.50€:
